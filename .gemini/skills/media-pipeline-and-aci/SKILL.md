# ACI 防错工具、批处理媒体管线与渐进式披露规范

## 一、 厘清三元扩展边界：Tool (ACI) vs. MCP vs. Agent Skill

1. **底层原子工具（Tools & ACI —— 肌肉与动作）**：模型直接调用的函数原语。
2. **模型上下文协议（MCP —— USB-C 万能扩展坞）**：通过“宿主-客户端-服务器”标准总线连接外部生图/生视频服务、音效库与本地软件，统一暴露 `Tools`、`Resources` 与 `Prompts`。
3. **模块化技能包（Agent Skills —— 岗位 SOP 手册）**：以 `SKILL.md` 为核心的文件夹，封装分镜布光、剪辑节奏、混音母带等专业视听方法论，教模型如何专业地组合工具。

## 二、 打磨防错型工具接口（ACI Poka-yoke 准则）

像打磨人类 UI 一样打磨给模型调用的接口，消除模型的机械计算负担：
- **强制使用 `asset_id` 句柄与标准时间码**：严禁要求模型心算像素字节偏移或音频采样帧数；接口参数应直接接受全局唯一的 `asset_id` 与直观的 `HH:MM:SS.mmm` 时间码或语义段落标记。
- **内置防错自愈提示**：当参数校验失败（如时间码超出素材总时长）时，返回包含素材实际时长与合法区间建议的结构化错误提示，引导模型单步自愈。

## 三、 批处理媒体管线模式（Media Pipeline / Code Mode）

- **核心痛点**：若让模型通过单步工具往返来剪辑 10 个镜头（查时长 → 切片 → 加滤镜 → 混音 → 烧字幕），需往返三四十轮，延迟极高且易断链。
- **架构准则**：针对本地多轨剪辑、批量图像后处理与音画合成，设计**声明式合成管线 schema 或受控媒体脚本模式**——让智能体一次性输出完整的合成流水线描述，由本地预热的媒体运行时在磁盘池内一次性高速执行完毕，仅向模型返回新生成的 `output_asset_id` 与校验摘要。

## 四、 三级渐进式披露（Progressive Disclosure）

严禁在启动时将所有 `SKILL.md` 全文和上百个 MCP 工具 Schema 塞入 System Prompt：
1. **Level 1（常驻目录）**：启动时仅注入技能名称与一句话触发描述（约 50 Token/项）。
2. **Level 2（按需挂载）**：命中创作意图时，动态加载对应 `SKILL.md` 正文与关联工具 Schema。
3. **Level 3（用后即焚）**：子任务执行中读取的参考色表、模板与工具原始日志，在交付句柄后立即卸载清理。
