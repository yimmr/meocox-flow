# 生成式 UI 选型矩阵与人机无冲突协同细则

## 一、 三大生成式 UI（Generative UI）范式选型矩阵

在 AIGC 桌面与 Web 应用中，应将“传输归属协议（AG-UI / MCP-Apps）”与“生成范式”解耦，按以下准则选型：

| 生成式 UI 范式 | 核心运作机制 | 宿主安全性与视觉一致性 | 界面自由度与扩展成本 | AIGC 应用中的最佳适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 静态映射型 (Static GenUI)** | 预先硬编码固定组件；模型仅选择组件 ID 并填入 JSON 参数。 | **极高**：完全受控于原生设计系统，零渲染错误，Token 消耗极低。 | **低**：每新增一种卡片形态均需前端发版。 | 高频固定系统控件：算力预算审批弹窗、渲染进度条、版本回滚确认卡。 |
| **2. 声明式组合型 (Declarative GenUI - 默认首选)** | 宿主定义原子 UI 积木目录（A2UI / OpenUI）；模型运行时自主决定布局并组合原语。 | **高**：自动继承宿主深浅色主题 Token，杜绝恶意脚本执行。 | **中高**：无需发版即可动态拼装千变万化的交互表单与对比面板。 | 对话流内嵌多模态参数推导器：色板盲测卡、多维情绪滑块、分镜局部重绘配置面板。 |
| **3. 开放式沙箱型 (Open-Ended GenUI)** | 模型实时编写完整 HTML/CSS/JS，由受控沙箱 Webview / iframe 渲染。 | **中**：需严格同源沙箱隔离，并注入宿主 CSS 变量以防视觉割裂。 | **极高**：不受预定义组件限制，可创造任意定制可视化预览。 | 独立画布中的交互式特效原型预览、动态数据可视化字幕模板、3D 镜头机位模拟器。 |

## 二、 消除“AI 覆盖人类手工微调”的双重保障机制

1. **多轨工程与结构化文稿接入 CRDT（如 Yjs）**：
   将分镜脚本、时间轴轨道节点建模为共享 CRDT 文档。人类在画布上的拖拽裁剪与 AI 在后台的流式追加各自生成带状态向量的增量更新（Update），在内存与磁盘层自动实现数学级无锁合并。
2. **普通配置文件执行“唯一锚点碰撞检测”**：
   对于未接入 CRDT 的结构化描述文件，智能体修改时严禁全量重写文件，必须传入修改处的上下文唯一锚点（`old_snippet` -> `new_snippet`）。若人类刚刚手工改动了该区域导致锚点不匹配，底层立即拦截写入并通知智能体先同步人类最新改动，彻底杜绝脏覆盖。
